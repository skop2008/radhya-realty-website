# Observation: Cross-Origin Live CMS Hydration & Dynamic Polling Pattern

## Context
Integrating a Next.js CRM backend with a static multi-directory public website using `BroadcastChannel`, `localStorage`, and Next.js REST API routes.

## Pattern Observed & Resolved
1. **Cache Control Preflight Rejection**:
   - `fetch('.../api/v1/cms/cards', { headers: { 'Cache-Control': 'no-cache' } })` triggers an HTTP OPTIONS preflight check. If `Access-Control-Allow-Headers` lacks `Cache-Control`, browser fetch fails.
   - **Fix**: Use query parameter timestamp (`?t=${Date.now()}`) instead of custom cache headers to avoid unnecessary preflight triggers, and explicitly declare `Cache-Control` in `Access-Control-Allow-Headers`.

2. **Playwright Navigation vs Rapid Polling**:
   - Rapid intervals (e.g. `setInterval(sync, 1500)`) prevent Playwright's `waitUntil: 'networkidle'` from resolving because outgoing network traffic never ceases.
   - **Fix**: Couple `waitUntil: 'domcontentloaded'` with event-based triggers (`focus`, `visibilitychange`, `BroadcastChannel`, `storage` events) and fallback to longer intervals (10s+).

3. **Default Accordion Toggle Guard**:
   - When an accordion item is already open by default (`.service-dropdown-item.open`), blindly clicking its trigger collapses it.
   - **Fix**: Check `isAlreadyOpen` before dispatching a click event in test scripts.
